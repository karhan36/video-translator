# Телеграм-бот перевода видео

Присылаешь ссылку на ролик — бот распознаёт речь, переводит на русский, озвучивает
синтезом и укладывает озвучку по таймкодам оригинала. В ответ показывает примерную
стоимость в рублях и три кнопки: **Видео**, **Аудио**, **Текст**.

Движок — официальный Yandex SpeechKit. Ни vot-cli, ни Node, ни прокси не нужны.

## Что внутри

| Файл | Зачем |
|---|---|
| `bot.py` | Бот на aiogram 3: whitelist, очередь на один ролик, кнопки, ленивая сборка файлов, автоочистка |
| `speechkit.py` | Движок: Object Storage, STT longRunning, Translate, TTS, потоковая укладка дорожки |
| `editor.py` | ИИ-редактор на YandexGPT: сверка с оригиналом, глоссарий, бюджет символов |
| `media.py` | yt-dlp и ffmpeg: скачивание, конвертация, `atempo`, сведение видео |
| `textout.py` | Субтитры `.srt` и текст `.txt` с абзацами |
| `config.py` | Все настройки из `.env` |
| `glossary.txt` | Словарь терминов EN→RU, пополняется вручную |
| `deploy.sh` | Развёртывание на чистой Ubuntu |
| `tests_offline.py` | Офлайн-проверки логики, без обращения к сервисам |

## Как работает пайплайн

1. **yt-dlp** качает звуковую дорожку.
2. **ffmpeg** переводит её в OGG_OPUS моно 16 кГц.
3. Файл заливается в **Object Storage** — асинхронное распознавание берёт аудио только оттуда.
4. **SpeechKit STT** (`longRunningRecognize`) распознаёт речь с таймкодами слов.
5. Слова собираются во фразы: режем по паузе `PHRASE_GAP` или по длине `PHRASE_MAX_CHARS`.
6. **Yandex Translate** переводит фразы. Батчинг по суммарной длине — лимит API 10 000 символов.
7. **ИИ-редактор** чинит перевод (см. ниже).
8. **SpeechKit TTS** синтезирует каждую фразу в сыром PCM.
9. **Укладка**: фразы пишутся в WAV потоково, между ними тишина — паузы автора сохраняются,
   аудио не растягивается.
10. Для видео дорожка накладывается поверх приглушённого оригинала.

Объект в бакете удаляется сразу после распознавания.

## Темп речи

Фраза ускоряется через `atempo`, только если реально не влезает в свой слот:

- порог `ATEMPO_MIN` (1.12) — мелкие расхождения не трогаем, иначе темп скачет от фразы к фразе;
- потолок `MAX_ATEMPO` (1.5) — выше голос ломается.

Главный рычаг против скачков — не `atempo`, а ИИ-редактор: каждая строка помечается
бюджетом символов по её тайм-слоту (`CHARS_PER_SEC`), и редактор ужимает перевод под
этот бюджет. Фраза чаще влезает сама, ускорение подключается реже.

## ИИ-редактор

Между переводом и синтезом стоит вычитка через YandexGPT — главный рычаг качества.

Ключевой приём — **сверка с оригиналом**. Редактор получает пару строк: оригинал
и машинный перевод, и чинит перевод, глядя на оригинал. Без этого не исправить
искажённые распознаванием имена и термины.

Термины держит единообразными по `glossary.txt` (формат `english = русский`).
В промт подмешиваются только те термины, что реально встретились в батче.
Пополняется вручную: дописал строку — редактор подхватил, код трогать не надо.

Работает батчами по `LLM_BATCH` строк. Жёсткое правило промта — не менять число и
порядок строк, они привязаны к таймкодам. Если батч вернул не то число строк или
запрос упал, этот батч откатывается на машинный перевод, синхрон не рушится.

Выключается флагом `LLM_EDIT=0`.

## Что нужно завести до запуска

**1. Yandex Cloud.** Сервисный аккаунт с ролями:
`ai.speechkit-stt.user`, `ai.speechkit-tts.user`, `ai.translate.user`,
`ai.languageModels.user`, `storage.editor`. Без последней STT не прочитает залитый файл.
Нужны API-ключ (для сервисов) и статический ключ доступа (для Object Storage).
Бакет создаётся ботом сам при первом запуске.

**2. Токен бота** от [@BotFather](https://t.me/BotFather) и свой Telegram ID.

**3. Ключи приложения Telegram** — `TELEGRAM_API_ID` и `TELEGRAM_API_HASH`
с [my.telegram.org](https://my.telegram.org) → API development tools.
Нужны локальному Bot API server. Без него Telegram режет отдачу файлов на 50 МБ,
и длинные ролики уйдут только текстом.

## Развёртывание

```bash
# на чистой Ubuntu, от root
apt update && apt install -y git
mkdir -p /opt/video-translator && cd /opt/video-translator
# положить сюда файлы проекта
cp .env.example .env && nano .env      # заполнить ключи
bash deploy.sh
```

`deploy.sh` ставит python3-venv, ffmpeg и Docker, собирает venv, поднимает контейнер
`tgbotapi` на 127.0.0.1:8081, прописывает ночную очистку кэша и запускает systemd-сервис
`vot-bot` с автозапуском и рестартом.

Логи: `journalctl -u vot-bot -f`

## Диск не засоряется

Рабочие файлы задания удаляются через `CLEANUP_MIN` минут после готовности.
При старте бот подчищает хвосты прошлых запусков. Кэш Bot API server чистится ночным
cron (файлы старше суток).

## Смета

После обработки бот показывает стоимость по фактическому объёму с разбивкой.
Тарифы Yandex Cloud (с НДС) задаются в `.env`:

- STT — `STT_RUB_PER_15SEC` (0,1515 ₽ за 15 секунд аудио)
- Translate — `TRANSLATE_RUB_PER_MCHARS` (500,4 ₽ за 1 млн символов)
- TTS — `TTS_RUB_PER_MCHARS` (1342 ₽ за 1 млн символов)

Ориентир: 5 минут ≈ 11 ₽, 40 минут ≈ 90 ₽, 2 часа ≈ 280 ₽.
Тарифы меняются — сверяйся с прайсом Yandex Cloud и правь `.env`, код трогать не надо.

## Ограничения

- Один синтезный голос на весь ролик, без разделения по спикерам — в публичном
  API SpeechKit этого нет.
- Лимит длины — `MAX_DURATION_MIN` (180 мин). SpeechKit держит до 4 часов и 1 ГБ на файл.
- Один ролик в работе за раз.
- Доступ только у владельца — whitelist по Telegram ID.

## Проверка логики без сервисов

```bash
python3 tests_offline.py
```

Прогоняет нарезку фраз, батчинг, укладку по таймкодам (включая пороги ускорения),
субтитры, абзацы, смету и разбор ответа ИИ-редактора. Сеть не нужна, ключи не нужны.
